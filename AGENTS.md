# AGENTS.md — go-verdict

The fleet's typed epistemic status library: a five-state `Verdict` type, one
`WorstOf` roll-up, one render grammar (`Icon`, `ExitCode`) — extracted once
from the ~14 dashboards and gate batteries that hand-rolled it (2026-11-21
domain-language census). Single Go package, module root, stdlib only.

## Non-negotiable contracts

These are the library's reason to exist; breaking any of them breaks consumers
fleet-wide:

- **Zero dependencies, stdlib only.** No third-party `require` lines in
  go.mod, ever. This is the adoption contract: stdlib-only consumers (gate
  batteries, CLIs, nix-hermetic builds) adopt it without a dependency
  discussion. A new require line is a design failure, not a convenience.
- **The state set is closed: five states.** `PASS FAIL WARN SKIP UNKNOWN` — no
  sixth state. Adding one is a contract change that requires updating the
  consumer census; `TestStateSetIsClosed` guards the cardinality.
- **String forms are a stable wire format** (JSON, SARIF, TSV across
  consumers). Never reword a state constant.
- **Semantic invariants** — each is a deliberate, load-bearing row in the
  `TestWorstOf` table, not incidental behavior:
  - empty or all-Skip input rolls up to `UNKNOWN` (an honest roll-up does not
    invent a Pass);
  - `UNKNOWN` poisons an otherwise all-Pass roll-up (unverified is not
    verified);
  - Skips never vote;
  - `Parse` refuses near-miss laundering: `"passed"` → `UNKNOWN`, never `PASS`;
  - `ExitCode`: only `FAIL` exits 1 — warn-as-error policy belongs to
    consumers; the type carries epistemics, not policy.

When changing the package, extend the existing test tables rather than adding
parallel suites: every row documents a decision a consumer depends on.

## Commands

- `buildflow` — the quality gate. No `.buildflow.yml` (all defaults); it
  auto-detects Go plus dprint (markdown/yaml/json). `buildflow --fix`
  repairs; `buildflow -s <tool>` drills into one step; `--format finding`
  lists findings. Do NOT hand-run `golangci-lint`, `dprint`, or
  `go mod tidy` — BuildFlow owns them (see the `buildflow` skill). golangci
  runs with the fleet-default `.golangci.yml` (generated by
  `buildflow -s golangci-lint-auto-configure --fix` — the step only
  configures an EXISTING file, so seed one first if it is ever deleted).
  A green run can still exit non-zero when error-severity findings remain;
  read the findings section, not just the exit code.
- A BuildFlow pre-commit hook gates every commit (`buildflow precommit
  install`; lives in `.git/hooks/pre-commit`): buildflow pre-commit mode on
  staged files — auto-formats and re-stages fixable findings, blocks the
  commit on unfixable ones (~3 s here). Uninstall with
  `buildflow precommit uninstall`.
- `go test ./... -race` — the test suite (also the documented contributor
  check, per CONTRIBUTING.md).
- No flake.nix — deliberate ("nix-hermetic by triviality", STACK.md). No
  Makefile, no justfile.

## Layout

- `verdict.go` — the entire library. The package doc comment is the domain
  language (states and their promises, roll-up ordering); read it first.
- `verdict_test.go` — the contract (see above).
- `STACK.md` — foundation decision record (stdlib-only; why not go-health or
  go-output). Re-derive before extending (see the `stack-selection` skill);
  it also names the revisit trigger: a render/SARIF layer growing past
  ~200 LOC.
- `README.md` — consumer ledger. Keep the Consumers section current whenever
  a repo adopts or evaluates-and-rejects the library; per ADR-0001 the
  library only counts as "shipped" once a consumer migrated.
- `FEATURES.md` — honest feature inventory by status; use only the five-label
  status vocabulary, every row cites evidence.
- `ROADMAP.md` — long-term raw ideas, non-goals, and Open questions. Open
  decisions route here, never into TODO_LIST.
- `docs/DOMAIN_LANGUAGE.md` — the ubiquitous-language glossary; the fleet
  census reads this file, so new domain terms land here first.
- `docs/status/` — point-in-time reports, historical by design: never
  rewrite one; annotate items inline when resolved. The newest report's open
  next-items MUST be harvested into TODO_LIST/ROADMAP — the docs-gates
  freshness gate fails the repo until they are.
- `TODO_LIST.md` — must exist and stay honest: docs-gates cadence reads it
  (a missing file trips the BuildFlow findings gate at error severity), and
  it holds actionable items only — done items are deleted, questions go to
  ROADMAP.
- `CHANGELOG.md` — keep-a-changelog style; append-only, cut a version
  section per release (fold `[Unreleased]` when tagging).

## Conventions

- One package at the module root, `github.com/larsartmann/go-verdict`. No
  `cmd/`, no `internal/`, no subpackages unless the library genuinely grows a
  second concept. A v2+ would require the module-path migration from the
  `go-release` skill.
- Tabs for Go; 2 spaces for YAML/JSON/TOML/Nix; LF everywhere
  (.editorconfig; .gitattributes pins `eol=lf`). No trailing-whitespace
  trimming inside Markdown (trailing double-space is meaningful there).
- `.gitignore` carries a buildflow-managed fenced block — edit outside the
  markers; the block is regenerated by `buildflow --fix`. `dprint.json` is
  gitignored below it on purpose: BuildFlow generates it per host with
  LOCAL plugin paths when `BUILDFLOW_DPRINT_PLUGINS` names a complete
  vendored bundle (this host's home-manager session exports it at
  `~/.local/state/buildflow/dprint-plugins/share/dprint-plugins`), and with
  remote URLs as the graceful fallback elsewhere. Never commit a
  `dprint.json`; a cold offline `buildflow -s dprint-format` must stay green.
- git-town: main branch is `master`; GitHub connector `api`.
- Dependabot: weekly gomod updates, minor+patch grouped, max 5 open PRs.

## Known findings and deliberate non-fixes

Check here before "fixing" what a linter reports:

- go-structure-linter's `internal-directory` warning is a deliberate
  non-fix: a single-file public library lives at the module root, full stop.
- The hand-curated `mapKey` exclusion in `.golangci.yml` (gocritic,
  `_test.go`) is policy, not debt: the whitespace in the `"  Fail "`
  test key IS the test — Parse trims it. An earlier companion suppression
  (`mnd` on `verdict.go`) was retired once `weight()`'s ranks became named
  constants. Auto-configure preserves curated rows; do not "clean them up".
- docs-gates (the battery tool) CANNOT adopt this library: it is itself
  stdlib-only by root-module contract and keeps its own three-word verdict
  vocabulary by design. Do not file adoption work for it; same for monitor365
  (pure-Rust workspace, no Go side). Both evaluated and closed.
- A `GOEXPERIMENT=jsonv2` set in the shell triggers a harmless buildflow
  doctor warning here (this package does not import `encoding/json/v2`).

## Gotchas

- An auto-git commit daemon runs continuously; expect commits you did not
  make, and verify state with `git status` before assuming. The pre-commit
  hook gates the daemon's commits too: a blocked daemon commit leaves the
  changes in the working tree, and formatter repairs the hook makes can
  surface inside daemon commits with generic messages — verify with
  `git log --stat` before trusting one.
- `reports/` is a gitignored scratch dir (coverage output) — never commit it.
- Releases: annotated tag per the `go-release` skill; fold CHANGELOG's
  `[Unreleased]` section into the version section when cutting.
